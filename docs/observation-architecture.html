02 / The input contract

A structured position, not a screenshot.

The native and Python encoders implement the same versioned representation. Most arrays are float32; action_focus is int32. Fixed capacities allow batching. Validity masks distinguish actual rows from padding. Overflow raises an error rather than silently discarding information.

How the network reads it
Important boundary

Numbers, categories and joins

Examples of numeric scaling: life ÷ 20; zone counts ÷ 60; mana and many counts ÷ 10. Phases and action families use one-hot flags. Card definition IDs and object indexes are references into other tables, not quantities to interpret as “larger” or “smaller.”

Effective state is already present

Permanent features include effective power/toughness and keyword flags. The agent need not reconstruct these from every effect. The additional fact records preserve open-ended state and effect provenance beyond those fixed columns.

03 / The 140-fact example

One effect can become many rows.

A fact is one typed statement about one player or permanent. Kinds include counters, added subtypes, set names/types, used abilities, continuous effects, copies and copy exceptions. A row carries the detail and provenance needed to interpret that statement.

fact vector = Linear(tanh(kind + ID bucket + detail bucket + source bucket + numeric projection))
object vector += sum(fact vectors whose object link names this object)

IDs reconstruct their two 16-bit halves and use 4,096 embedding buckets; bucket collisions are possible. Numeric input has five values: two amounts, two duration indicators and timestamp rank ÷ 128. That timestamp scale stays fixed when capacity changes. The output projection starts at zero.

Interactive example · repeated Drill effects

Seven mana, seven activations.

The Fire Nation Drill has “{1}: Permanents your opponents control lose hexproof and indestructible until end of turn.” No tap cost. Repeating it against an unchanged board is redundant, but the current representation retains separate timestamped effects.

04 / Inside the neural network

Small attention; substantial semantic tables.

Card meaning comes from programs

The semantic encoder builds token sequences from native rules definitions, including referenced definitions and program boundaries. A learned token embedding and GRU turn each complete sequence into a 64-dimensional vector. The snapshot has 331 definitions and 766 unique tokens; the longest expanded program is 713 tokens.

This GRU runs along a card's definition. It is not memory of earlier turns. A definition vector is reused wherever that card is referenced in the observation.

Attention connects visible objects

Each valid object can exchange information with the other valid objects. Four heads look at different learned projections of the same 64 channels. Padding is excluded as attention keys and its output is zeroed. Two blocks refine the representation before the actor and critic read it.

Actions do not join this self-attention sequence. Each action separately gathers up to two relevant object vectors, along with current continuation context, before being scored.

Parameter ownerCountShare of total

Counted from an instantiated CPU model, without running games or training: 1,079,490 parameters. Fact tables dominate: three 4,096 × 64 embeddings, kind embeddings, numeric and output projections. Buffers, optimizer state and runtime activations are excluded.

What is enabled, and what is not?

Enabled: semantic card programs, effective object features, facts, attachment/blocking joins, current continuation context, two object-attention blocks, legal-action head, scalar critic with masked mean.

Disabled in this pilot: recent-event encoder (history version 0), recurrent compound-action decoder, policy FiLM, explicit belief rows, value token and categorical win/draw/loss head. These are separate configuration choices; their presence in the repository does not mean this pilot uses them.

Current continuation is not past-game memory

The 64 relation rows describe the current stack, parent/frame links, targets, pending choices and waiting triggers. The relation encoder joins two object vectors and two card-definition vectors to numeric features, then projects 300 → 64 → 64 with tanh. A valid-row mean informs every object and action. Per-frame pooled vectors also join the actions that reference that frame. This computation carries no hidden state across decisions.

Knowledge and visibility

Known-hand entries multiply definition vectors by counts ÷ 60 and sum into each player's vector. Decklists produce four separate count-weighted pools—main, unseen, sideboard and remaining sideboard—then project their concatenation from 256 to 64. The engine owns disclosure. A closed opponent's decklist rows are zero, and an open decklist does not expose the actual order of the library or the identity of every hidden card in hand.

05 / A separate design question

What should be state, history, or memory?

Proposed direction · not implemented by the capacity hotfix

Jack Heart proposed sharing effects across permanents, presenting the resulting permanent directly, and considering history and agent memory together. These are connected choices: a more compact board representation needs a clear account of where omitted information remains available.

Effective stateWhat is true now: power/toughness, abilities, counters, controller and legal choices. Many of these features already exist.
Shared effectsDescribe an effect once, with exact affected-object links, source, duration and meaningful ordering. A fixed set must not accidentally include later entrants.
History + memoryPreserve visible events and useful past information. Define what survives a window limit, turn boundary, replay, fork or restored checkpoint.

For the Drill, a possible representation is seven effect records with two keyword details and explicit links to the ten affected permanents. That replaces repeated effect payloads, but still needs membership links. Further combining redundant records requires a rules audit; it is not just deleting duplicate rows.

The sufficiency test: two permanents can have the same effective characteristics now and behave differently when an effect expires or a source leaves. A history window can also forget an event whose effect remains active. The new contract must either expose that distinction in state or reliably preserve it through history/memory.

The separate design task should compare a stateless sufficient-state representation with history/memory alternatives. It must preserve viewer safety, semantic distinctions, checkpoint identity and training/serving consistency. A recurrent policy is an option to evaluate, not a foregone conclusion.
