02 / The input contract

A structured position, not a screenshot.

The native and Python encoders implement the same versioned representation. Most arrays are float32; action_focus is int32. Fixed capacities allow batching. Validity masks distinguish actual rows from padding. Overflow raises an error rather than silently discarding information.

How the network reads it
Important boundary

Numbers, categories and joins

Examples of numeric scaling: life ÷ 20; zone counts ÷ 60; mana and many counts ÷ 10. Phases and action families use one-hot flags. Card definition IDs and object indexes are references into other tables, not quantities to interpret as “larger” or “smaller.”

Effective state is already present

Permanent features include effective power/toughness and keyword flags. The agent need not reconstruct these from every effect. Local facts preserve counters, subtype/name changes, used abilities and copies. Shared effect records separately preserve complete modifications, exact source/controller joins, expiry and timestamp order.

03 / Shared effects

One payload, many explicit members.

V7 factors complete equal native payloads before capacity admission. Seven Drill activations over ten objects become 7 payloads and 70 memberships; the retained nine-activation, fifteen-object case becomes 9 payloads and 135 memberships. Each activation keeps its timestamp and both keyword details. Rules records stay intact. The fact-column inspector below documents the frozen v5/v6 fragment format; v7 uses it only for local facts and copy exceptions.

128 complete headers × 18Modification, three optional amounts with presence flags, duration, timestamp rank, controller, source definition and exact source-object join. Offsets/counts address details and members; the last column is validity.
512 detail tokens × 3Keyword, subtype or color kind plus a vocabulary ID split into exact 16-bit halves. Each detail appears once per shared payload.
2,048 memberships × 2One-based object-table join and original record ordinal. Duplicates remain separate edges. Zero-filled unused rows are outside the header slices.
payload = Linear(tanh(sum(modification, source-definition, header, typed details)))
object[j] += sum(payload[e] for each membership e → j)
existing object attention → unchanged focus-object gathers → action logits

Controller and exact source gather existing object embeddings before payload reduction. Object IDs and offsets are routing addresses, never numeric features. Timestamp rank carries semantic order; original record ordinals support exact expansion rather than becoming learned numbers. All target losses backpropagate through the shared payload. The optional typed-GRU treatment replaces the within-record sum; it has no turn-to-turn memory.

The bounded sparse layout uses 31,744 padded bytes per observation for the three effect blocks, plus 6,144 bytes for 128 local facts. The retained 270-fragment example has 1,944 active effect bytes (9 headers, 18 details, 135 edges), versus 12,960 active old fragment bytes. The allocated v7 blocks are larger than a v6/256 fact table (12,288 bytes); active compaction is not a padded-memory saving.

With 202 object slots, a dense 128 × 202 float32 incidence matrix alone costs 103,424 bytes; a boolean matrix costs 25,856 but loses duplicate counts and original order. Sparse edges preserve both without adding attention tokens. Per-observation neural work scales with active payload/detail/member counts, followed by the existing object attention. The current implementation iterates active payloads; CUDA throughput is not established by these CPU checks.

Unnormalized sums preserve multiplicity: two identical memberships contribute twice. A mean would erase that distinction; count-aware normalization is a separate architecture experiment. Summed learned vectors can alias and grow with counts, and the payload tanh can saturate. Exact transport does not make the learned embedding injective or prove stronger play.

IDs reconstruct their two 16-bit halves and use 4,096 embedding buckets; bucket collisions are possible. Numeric input has five values: two amounts, two duration indicators and timestamp rank ÷ 128. That timestamp scale stays fixed when capacity changes. The output projection starts at zero.

04 / Inside the neural network

Small attention; substantial semantic tables.

Card meaning comes from programs

The semantic encoder builds token sequences from native rules definitions, including referenced definitions and program boundaries. A learned token embedding and GRU turn each complete sequence into a 64-dimensional vector. The snapshot has 331 definitions and 767 unique tokens; the longest expanded program is 713 tokens.

This GRU runs along a card's definition. It is not memory of earlier turns. A definition vector is reused wherever that card is referenced in the observation.

Attention connects visible objects

Each valid object can exchange information with the other valid objects. Four heads look at different learned projections of the same 64 channels. Padding is excluded as attention keys and its output is zeroed. Two blocks refine the representation before the actor and critic read it.

Actions do not join this self-attention sequence. Each action separately gathers up to two relevant object vectors, along with current continuation context, before being scored.

Parameter ownerCountShare of total

Counted from an instantiated CPU model, without running games or training: 1,879,170 parameters. Local-fact and shared-effect vocabulary tables dominate. V7 adds its own modification/detail/source embeddings, header projection and payload reducer. Buffers, optimizer state and runtime activations are excluded.

What is enabled, and what is not?

Enabled: semantic card programs, effective object features, local facts, shared effects, attachment/blocking joins, current continuation context, two object-attention blocks, legal-action head, scalar critic with masked mean.

Disabled in this configuration: recent-event encoder (history version 0), recurrent compound-action decoder, policy FiLM, explicit belief rows, value token and categorical win/draw/loss head. These are separate configuration choices; their presence in the repository does not mean this configuration uses them.

Current continuation is not past-game memory

The 64 relation rows describe the current stack, parent/frame links, targets, pending choices and waiting triggers. The relation encoder joins two object vectors and two card-definition vectors to numeric features, then projects 300 → 64 → 64 with tanh. A valid-row mean informs every object and action. Per-frame pooled vectors also join the actions that reference that frame. This computation carries no hidden state across decisions.

Knowledge and visibility

Known-hand entries multiply definition vectors by counts ÷ 60 and sum into each player's vector. Decklists produce four separate count-weighted pools—main, unseen, sideboard and remaining sideboard—then project their concatenation from 256 to 64. The engine owns disclosure. A closed opponent's decklist rows are zero, and an open decklist does not expose the actual order of the library or the identity of every hidden card in hand.

05 / History and memory

Active effects outlive a history window.

V7 keeps active payloads in current viewer-safe state. Two objects with the same effective keywords can diverge when an effect expires or a particular source leaves. A bounded event suffix cannot reconstruct an effect whose creation is absent or has been evicted.

The model remains stateless across decisions. Persistent per-seat memory is deferred; it would require explicit ownership, reset/fork/restore behavior, sequence training and serving parity. The shared-effect repair proves engineering correctness on directed cases, not full-game learning improvement. No scientific comparison seed has run.
