Already launched · MTG-241

A choice is a pause in owned state.

A nested effect must be able to ask a player a question, survive a search fork, and resume the exact child before the parent proceeds. The current iteration path explicitly assumes children never ask questions.

Parent iteration→Child asks a choice→Fork preserves both→Command resumes child→Parent advances once

Replacement selection uses the same suspension contract: retain the event proposal, affected chooser and applied replacement identities; re-evaluate applicability after a choice; commit once. Simultaneous events remain simultaneous even when choosing their replacements takes several decisions.

Acceptance trace: stop during a child’s object selection, fork, make different legal choices, and replay each branch. Neither branch repeats payment, skips an iteration, exposes private information or finalizes the spell twice. Stale Commands fail without changing the pending state.

Proposed Tasks 01–02

Casting asks four separate questions.

Which spell? From where? Under which permission? What was actually paid? Today these responsibilities are partly expressed through small cast flags and an exile-specific grant. Extend their owners instead of giving every new mechanic a casting executor.

Existing exact-object grants already supply part of the foundation

For Muldrotha, the permission reads a graveyard and a type quota. Omniscience changes the mana-cost payment rule while retaining applicable additional costs. An Omen or Adventure chooses a spell profile; it is not a battlefield transform. Each case should reuse the same announcement and payment path.

MTG-242 remains the mana feasibility/resource authority. Task 01 adds nonmana obligations and casting receipts around it. Task 02 replaces overlapping grant flags and casting special cases as consumers migrate; there should be one active implementation for each rule.

“Transaction” means retained rules progress, not a public undo button. Costs and revealed information cannot be erased by browser cancellation. Rules-mandated handling of an illegal action is a separate engine contract.

Proposed Tasks 03, 05–06

Read actual events. Keep exact lifetimes.

Fumigate needs the creatures actually destroyed. A death-trigger value may need last-known characteristics. A cast trigger may need mana actually spent. These are different reads, but their subjects and scopes can share a vocabulary.

These are contract sketches, not a proposal for an unrestricted query language or a universal record table. Extend EffectValue, existing event counters, ObjectRef, LKI, copy records and effect records where they already own the fact. Instruction results stay in execution frames; history stays in its scoped owner; emblems and persistent grants have their own declared lifetime.

Layers remain one characteristic authority. Adding color, ability loss or dependency support there should improve every caller. Cache revisions must cover new reads—such as tapped status or off-battlefield characteristics—rather than letting a fast stale answer become the rule.

The learner sees the same decision: new state and choices must reach native and Python policy encoders, LLM text, learning tokens, replay/forks and Academy where applicable. Preserve frozen input versions. Viewer projections must not expose private information or collapse strategically distinct actions.

First, learn how to train on an uneven card pool.

MTG-245 — Design training and evaluation for growing card pools is a separate research Task ahead of the training runs. Compare curated decks, constrained generated decks and mixtures; choose how to sample old anchors and new mechanics; define stable benchmarks and held-out splits. Show the protocol through two successive uneven batches, such as Adventure/prepare followed by planeswalkers.

The research begins before engine work finishes. Task 04 then executes the first bounded training campaign on an integrated snapshot; Task 08 executes the later campaign. Both must deliver measured results. MTG-245 supplements these runs, bringing the near-term plan to nine new Tasks. Read the Task brief.

Two different kinds of training evidence.

Training is planned work with its own Tasks and retained results. A short operational campaign asks whether this engine is still a sound training environment. A deeper campaign asks how far the model can learn and transfer.

A crash is a reproducible engine input.

Capture the world and observation versions, checkpoint/configuration identity, decklists, seed and RNG state, Command tape, pending decision, original error, and actual capacity counts. Keep private state in access-appropriate debugging evidence. Replay the failing transition in debug and turn the minimal cause into a directed regression.

Look for integer, action, fact and object-capacity failures during ordinary bounded collection and controlled fixtures. An overflow report is not fixed by silently truncating legal actions or observations. No synthetic stress load or unbounded game cohorts.

Separate speed, learning and changed rules.

  • Engine: existing same-runner Engine Budget for steps and search, with equivalent counts/digests when semantics are unchanged. Keep the cumulative milestone anchor as well as the latest reference.
  • Training: end-to-end collection/update throughput, sample efficiency and fixed-opponent performance. A faster native step alone does not establish faster learning.
  • Evidence: version rule changes and scope affected conclusions. Use compatible checkpoints or paired fresh training; never relabel frozen worlds or regenerate old evidence to disguise a change.

Actual run budgets, available hardware and pass criteria belong in each experiment design before execution. No performance numbers or training outcomes are claimed by this walkthrough.

After FDN · Prefer the newer surviving sets

Rough preference: FRA → HOB → MSH → SOS → TMT → ECL, then close TLA’s remaining coverage and work back through SPM, EOE, FIN, TDM and DFT. Move a prerequisite mechanic earlier when it reduces duplicated work—for example, prepared spells shared by SOS and FRA—without requiring that prerequisite’s entire set to finish first.

The 13 reviewed surviving sets contain 3,526 distinct Oracle identities in the research snapshot. That is not a legal-deck denominator: bans, reprints, special products and non-deck-entry faces need reconciliation. Star Trek and the rotation-triggering Nauctis release also require fresh inventory reviews; the currently released survivor pool is not the entire future post-rotation format.

Budget and replanning

Four foundation Tasks + nine new Tasks leaves at most 36 further Tasks under a 49-Task ceiling, including authoring, ordinary validation, deeper assessments and repairs. This is a planning constraint, not an effort guarantee. Replan at each milestone using measured reuse, coverage and runtime cost; retain reserve rather than turning the remaining work into dozens of premature commitments.

Full card-file support, Standard legality and complete best-of-three tournament procedure are distinct deliverables. Opening-hand behavior is required by FDN cards and is included; between-game sideboarding needs an explicit product decision before a tournament-complete claim.
