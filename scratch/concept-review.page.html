The biggest mismatch: patching around vector-wide policies and halfway-compact records instead of finishing the ownership boundary

The plan treats per-slot native policies and compact decision evidence as local optimizations inside vector.py rather than finishing the model where each fact is owned. Walking both a normal round and a failure exposes four concrete breaks:

  1. Multi-slot records and slot reuse still assume one vector-wide policy pair. GameRecord stores one player_policies tuple for all games, GameInputs has none, SlotLoad::Fresh inherits the previous leg's policies via previous.replacement_root(), and SlotLoad::Snapshot checks against self.player_policies. If a multi-slot failure snapshot or journal is written while slot 0 is ("agent", "heuristic:64") and slot 1 is ("heuristic:64", "agent"), replay_failure_inputs replays half the slots with the wrong seat as heuristic.
  2. Halfway-compact annotations still pay for full observations every round. GameInputs.digests[i] already Blake3-hashes the entire ActionSpace and GameInputs.actions[i] is the chosen offer index. Dropping frame_sha256 while keeping chosen_offer and action_space_kind forces step_round to keep calling vector.decision_observations(active) (cloning 64 full native Observation structs across PyO3) and describe_actions(raw) every round — even though no downstream consumer reads either field from a GameRecord (audit_view only reads chosen_offer["id"], which equals inputs["actions"][index]).
  3. RecordedVectorEnv._step duplicates Rust's semantic frame serialization. On every isolated step, RecordedVectorEnv._step calls semantic_decision_frames_json(active) in Python even with no journal and no policy probabilities, while Rust's step_isolated_with_writer serializes the exact same frame a second time into info["game_error_frame"].
  4. agents.py overloads Heuristic and misses why state was lost. manabot/sim/heuristic.py:HeuristicPlayer is already stateful (standalone scalar execute_game builds one per game). State is lost because GamePlayer has no per-game lifecycle and agents.py:Heuristic calls factory(seed) inside choose().

Plan as written (halfway boundary)

  • GameRecord.player_policies stays record-wide; only take_slot_record patches it. Multi-slot snapshots/journals write wrong policies for swapped seats.
  • agents.py keeps one Heuristic(factory) class; vector.py peeks at match.players to detect built-in heuristic; plan edits sim/heuristic.py just to bump its hash.
  • Vector annotations drop frame_sha256 but keep chosen_offer + action_space_kind → still calls decision_observations(active) + describe_actions + duplicate semantic_decision_frames_json every round.
  • Opening heuristic turns run in unisolated reset/load_slots; mid-game heuristic crashes blame the checkpoint.

Recommended model (one owner per fact)

  • Each slot's Env and GameInputs owns its optional player_policies (omitted when matching GameRecord.player_policies; single-game records keep GameRecord.player_policies). PlayerPolicy::Heuristic { max_actions } serializes as "heuristic" / "heuristic:64" everywhere.
  • Split NativeHeuristic(max_actions) from CodeSeat(factory); give GamePlayer a per-game handle (open_game(seed)) so every stateful code player keeps turn state naturally without artificial edits to sim/heuristic.py.
  • Compact vector annotations store only runner-owned facts (actor, revision, player_id, player_seed, player_decision_ordinal, policy_rng_seed, latency_seconds) → zero decision_observations or describe_actions calls against native heuristic; RecordedVectorEnv pulls game.frame from info["game_error_frame"] only on failure.
  • Isolate opening settlement per slot and return game_error_seat on isolated native errors so every crash isolates cleanly and attributes to the acting seat.

Findings

What breaks: Putting per-slot policies only in take_slot_record leaves multi-slot failure snapshots/journals (_snapshot(), _write_game(), replay_failure_inputs()) writing one vector-wide policy pair for swapped seats. In Rust, SlotLoad::Fresh calls previous.replacement_root() (which would inherit the previous leg's policies when policies are omitted), derived serde on PlayerPolicy::Heuristic { max_actions } would break GameProvenance/SnapshotReplay string encoding, and env.rs:738,748 checks contains(&PlayerPolicy::Heuristic) which won't match a capped variant. In Python, agents.py:Heuristic conflates built-in native heuristic with arbitrary CodePlayers and rebuilds them on every choose() because GamePlayer has no per-game lifecycle — while sim/heuristic.py is already stateful.

Fix:

  • Custom string Serialize/Deserialize/Display/FromStr on PlayerPolicy ("agent", "random", "heuristic", "heuristic:64") and a PlayerPolicy::is_heuristic() helper in env.rs.
  • SlotLoad::Fresh defaults omitted policies to VectorEnv's default self.player_policies, not the slot's previous Env; SlotLoad::Snapshot restores its own policies.
  • Add optional player_policies: tuple[str, str] | None = None (excluded when None) on GameInputs so multi-slot snapshots and replay_failure_inputs preserve per-slot policies, while single-game records keep GameRecord.player_policies for backward compatibility.
  • Split NativeHeuristic(max_actions) from CodeSeat(factory) in manabot/eval/agents.py, and add a per-game lifecycle on GamePlayer (e.g., open_game(seed) or per-game reset) so both runners keep turn state for every stateful code player without editing sim/heuristic.py artificially.
  • Identity warning (irreversible once published): Changing heuristic_source_paths() (e.g., adding player_policy.rs or bumping anchor version) changes BOTH Etude's Code player key and EvaluationKey.anchor_cohort_sha256 → derive_seed for 100% of games, affecting stored tla_trophies* benchmarks. Decide explicitly in Q2 before Pass 1.

What breaks: When the native heuristic sits in seat 0 (legs 1 and 2 of every deal), Env::reset runs settle_players for all opening heuristic turns before the checkpoint acts. Neither reset_each_into_buffers nor load_slots_into_buffers isolates native AgentError or panics — one bad opening leg aborts the entire 64-slot batch. And during mid-game step_isolated_with_writer, vector.py:758 attributes any game_error to round_result.players[slot] (always the checkpoint), even when the error happened inside the heuristic's settle_players loop.

Fix:

  • Return game_error_seat in isolated step receipts (captured from the active chooser in step_once vs settle_players) so vector.py attributes crashes to leg.game["seat_players"][seat] rather than blindly blaming candidate or opponent.
  • Isolate per-slot opening settlement (either an isolated mode on load_slots_into_buffers/reset_each_into_buffers or isolating Env::reset's settle_players phase into SlotState::Poisoned + receipt) so a seat-0 heuristic error fails only that leg and frees the slot.

What breaks / wastes work: Dropping frame_sha256 while keeping chosen_offer and action_space_kind leaves step_round calling vector.decision_observations(active) (64 full PyObservation clones/round) and describe_actions(raw) live and in replay, even though no downstream consumer reads either field from a GameRecord and GameInputs.digests[i] + actions[i] already bind the exact offer set and choice. Meanwhile RecordedVectorEnv._step calls semantic_decision_frames_json(active) every round even when isolated=True, no journal is active, and no annotation carries probabilities — duplicating Rust's step_isolated_with_writer frame capture.

Fix:

  • In compact vector annotations, store only runner-owned facts that the engine cannot recompute (actor, revision, player_id, player_seed, player_decision_ordinal, policy_rng_seed, latency_seconds). Call vector.decision_observations only for slots with a custom Python CodeSeat.
  • In audit_view, derive offer_id from inputs["actions"][index] when chosen_offer is absent (falling back to chosen_offer["id"] for semantic Command strings). In _replay_record, verify frame_sha256, chosen_offer, and action_space_kind when present, and always verify actor + player_id.
  • In RecordedVectorEnv._step, skip semantic_decision_frames_json(active) when isolated=True, _game_journal is None, and no annotation has probabilities; on isolated game_error, copy info.get("game_error_frame") onto game.frame so replay_failure retains exact matches_binding == True.

What breaks:

  • Removing clone_env() from RecordWalker.run() mutates self.env's card capture before detecting a post-transition digest mismatch, directly breaking tests/env/test_record_reducers.py:105-113 and RecordWalker.cards()'s documented contract.
  • PyEnv::reset, PyEnv::step, and PyEnv::state_digest (managym/src/python/bindings.rs:4099-4396) hold the Python GIL, so a 2-thread replay pool serializes on the GIL and stalls the asyncio stepping loop instead of running concurrently.
  • experiments/eval_throughput.py:237 computes other_arena = seconds - timing.seconds - replay_seconds, which becomes invalid (even negative) once replay overlaps with forwards.

Fix:

  • On the fast path (apply is None, integer action, no next-boundary interventions), step self.env directly and check state_digest() once (checking digests[0] once after reset; 0 clones, 1 digest per step). Only on the cold divergence path, if self._capture_cards is enabled, rebuild self.env through the verified prefix 0..index before stopping so cards() stays exact without any new flag.
  • Wrap PyEnv::reset, PyEnv::step, and PyEnv::state_digest (including locking self.inner) in py.allow_threads(...) so background replay threads run genuinely in parallel with each other and with the stepping loop.
  • In eval_throughput.py, track main-loop wall stages separately from background replay thread time instead of subtracting overlapping worker seconds from total wall time.

What's awkward: manabot/infra/provenance.py:runtime_fingerprints re-hashes every .rs file and the ~40 MB _managym binary and constructs/resets a throwaway Env on every call (2.1 s of the 2.3 s admission profile). Adding a per-run cache inside vector.py leaves scalar play, admission, and registration paying the same cost. Similarly, manabot/sim/native_game.py:292 deep-copies immutable setup metadata 3×/decision when _Capture already provides frozen_context (managym/recording.py:630,853).

Fix: Factor and @cache the process-constant engine/source/content-manifest fingerprints inside manabot/infra/provenance.py (matching managym/recording.py:runtime_identities), and set capture.frozen_context once setup completes in execute_game (refreshing only on integrity/failure changes).

Unstated consequence of Design item 1: Moving vector heuristic evaluations from ("agent", "agent") to ("agent", "heuristic:64") / ("heuristic:64", "agent") means managym/academy/watch.py:486 will reject every new vector heuristic evaluation record with ValueError("Academy requires both seats' surfaced decisions; native-seat records are not yet viewable"). Because the game is fully deterministic from its record, Watch can reconstruct native-seat decisions on import by walking the record with an ("agent", "agent") view and replaying the heuristic's choices, or surfacing native turns — that is a separate Academy Task, not vector eval throughput, but it should be tracked explicitly rather than discovered when someone tries to inspect a trophy game.
