Biggest remaining mismatch (separate outcome): divergent decision-memory label admission

With MTG-504's own vocabulary split and historical ledger aligned, the only remaining mismatch in the reviewed area is pre-existing in Python admission and stands out more clearly now that decision_memory_names() is a first-class surface:

Current (two divergent checks)

  • Dense / retained-prefix path (decision_memory.py:498–504): checks kind and choice_kind only against the running engine's decision_name_values(), ignoring the checkpoint's tables.record_name_keys. An incomplete checkpoint table passes admission and mis-indexes in _prepare_memory_rows.
  • v11 native path (admission.py:394–398): checks only tables.record_name_keys under RecordNamespace.TOKEN, which accepts any non-memory token name (e.g. "flying") and skips the check when decision_memory == "none".

Recommended (separate follow-up Task)

  • Share one helper enforcing both invariants on decision-memory kind and choice_kind: membership in decision_name_values() and presence in tables.record_name_keys whenever the model reads memory rows.
  • Add a regression test covering an incomplete checkpoint table on retained prefixes and a non-memory TOKEN name on v11 batches.
