    Failure in HEAD: help_obligations → tap_obligations flattens {1}{G} into [Obligation::Pay { cost: {G}, taps: Taps::None }, Obligation::Pay { cost: {1}, taps: Taps::Keyword }]. Biggest mismatch: pre-flattened tap_obligations + DelveCost side-channel inside CoupledSearch

The pure solver flattens a helped cost into ordered tiers because tap order cannot mutate the board:

Reusing that flattened list beside a Delve-only side-channel in coupled.rs creates three fragile seam conditions:

Clears permissions.help.delve using initial self.payment.profile, producing split obligations in concrete. saved_delve = None drops Delve as soon as self.spend pays only the first split tier (obligations[0]). Inspects only obligations.first(): generic Improvise, Waterbend, and off-color Convoke taps live in obligations[1] behind colored pips, so taps == Taps::None exits early. Gating next_delve on self.payment.profile.stateful_delve() drops delve after a Convoke tap on sacrifice-coupled boards.

Built at HEAD (52fb812008)

  • CoupledPayment.delve: Option<DelveCost> tracks only Delve; Convoke, Improvise, and Waterbend rely on pre-flattened tap_obligations tiers.
  • try_help_taps reads only obligations.first(), returning None when colored pips sit ahead of generic Improvise/Waterbend/Convoke tiers.
  • try_help_taps gates next_delve on stateful_delve(), dropping delve after a Convoke tap when coupling came from a sacrifice mana source.
  • expand() sets saved_delve = None before self.spend on obligations[0], losing Delve on any remaining split tier.
  • CoupledMemoKey::hash hashes only delve.cost (omitting permissions.waterbend, colliding waterbend-remaining states).

Aligned design (one HelpedCost in CoupledSearch)

  • Rename DelveCost → HelpedCost and attach it for any helped cost (help != Help::default() || waterbend > 0) on a coupled model; ignore it on SourcePolicy::FixedOnly.
  • help_obligations builds concrete only for the pure handoff; native search steps operate directly on HelpedCost without splitting tiers.
  • try_help_taps tests every legal Convoke (colored or generic), Improvise (generic), and Waterbend (generic) tap directly against helped.cost and helped.permissions, always advancing via helped.after_pip(color, waterbend) (preserving delve unconditionally).
  • expand() spends the full remaining helped.cost (less graveyard Delve cards when !profile.stateful_delve()) in one self.spend transition, then continues to Obligation::PayLife(helped.life).
  • CoupledMemoKey::hash hashes (&helped.cost, helped.permissions.waterbend); uncoupled boards remain untouched.

Findings

Scope: This work (closes the remaining coupled-authority rule gaps introduced in Pass 5).

What breaks:

  • Generic Improvise, Waterbend, or off-color Convoke taps needed before a tapped-reading mana source are invisible to try_help_taps because tap_obligations places colored pips at obligations[0] and try_help_taps checks only obligations.first().
  • Convoking a non-tapping sacrificing creature (e.g., Skirk Prospector) before sacrificing it to fund Delve fails because line 850 drops delve whenever stateful_delve() is false.
  • Spending only the first tier of a split concrete obligation drops delve on the tail via saved_delve = None.

Recommendation: Generalize DelveCost to HelpedCost in coupled.rs (populated by track_helped whenever help != Help::default() || permissions.waterbend > 0, ignored on SourcePolicy::FixedOnly) so try_help_taps, DelveExile, and full-cost spend operate on one unsplit cost record; use profile.stateful_delve() from the current fork's board and hash waterbend alongside cost in CoupledMemoKey. Add focused tests for (a) Improvise/Waterbend tap enabling a tapped-reading mana source for a colored pip and (b) Convoke-then-sacrifice+Delve.

Passed over: Patching try_help_taps to loop over obligations indices while keeping DelveCost separate (leaves the dual representation, the paying_delve_cost/saved_delve flags, and the partial-tier spend split in place).
