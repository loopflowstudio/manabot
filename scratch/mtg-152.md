## Risk findings (2026-10-18)

1. **Greedy's target side is set by its seat, not by the card.** Engine target
   offers come in absolute order (Player 0, Player 1, then P0's battlefield,
   then P1's; stack spells first for `spell_or_permanent`), and v1 takes the
   first non-decline offer. Arena legs alternate seats, so each MTG-137 cell
   mixes both behaviors. Source: `managym/src/flow/triggers.rs::legal_targets_for_spec`,
   `flow/action.rs::pending_choice_action_space`, `content/semantic/v1/two_deck.source.json`.

   | Deck | Card (count) | Effect | v1 at seat 0 | v1 at seat 1 |
   | -- | -- | -- | -- | -- |
   | Lessons | Firebending Lesson (4) | 2/5 dmg to creature | own creature if any | opponent creature |
   | Lessons | Igneous Inspiration (2) | 3 dmg creature/player | **always itself** | opponent face |
   | Lessons | Divide by Zero (2) | bounce spell/permanent | top stack spell, else own | top stack spell, else opponent |
   | Lessons | It'll Quench Ya! (2) | counter unless 2 | top stack spell | top stack spell |
   | Allies | Fancy Footwork (2) | untap +2/+2 up to two | own first | **opponent creature** |

   Other targeted cards are side-restricted by selector and correct under v1.
   Removal dominates pumps (Lessons: 10 harmful targeted of 23 nonland;
   Allies: 2 beneficial). Frequency is unmeasured: this is code reading.
2. **The evaluation path MTG-118 uses cannot reach v2.** Checkpoint scoring
   goes `MonitorProtocol.opponent: Literal["scripted_greedy", "random"]` →
   `monitor_evaluation._manifest` → `arena/match.py::play_cell` →
   `arena/guidance.py::build_arena_player` → `arena/players.py::build_player`.
   v2 is registered only in the Study factory (`study/record.build_player`).
3. **Any edit to `arena/players.py` changes v1's identity.** The monitor's v1
   registration pins `file_sha256(players.py)`, and
   `run_skill_arena.registration_source_paths` digests it for scripted greedy
   and demo search. `build_arena_player` is the existing additive seam
   (precedent: `policy_prior_puct` with its own source digest), so v2 enters
   there and `players.py` stays byte-identical.
4. **Cost is bounded by game time.** MTG-137's diagnostic sidecar scored 208
   games under a 30-minute ceiling (≤ 9 s/game, one policy thread). Scripted
   vs scripted/random games are faster than policy games.
5. **Unverified:** native Study `_decision` over a real target prompt (unit
   tests use fakes; no local games); which MTG-137 checkpoints are retained
   and readable from this branch (the Task table lists Mini 10k ×3 seeds and
   GPU seed 12261 at 10k/25k). Both are checked first in the remote job and
   are admission failures, not silent omissions.

## Chosen approach

Make v2 a first-class arena/monitor anchor, then run one frozen, exploratory
headroom cohort that answers all three Task questions on paired deals. Add a
stronger rung only if the evidence says v2 also saturates.

### Built (PR #313)

- `study/targeting.py::inspect_target` records each target choice's source card
  and viewer-relative side on Study Decision records; trigger-sourced prompts
  and stack-spell targets stay `unknown`/unresolved rather than guessed.
- `experiments/runners/greedy_targeting.py` audits retained records offline by
  source, cell and seat, keeping declines, unknowns, unmeasured legacy prompts
  and unfinished games explicit. Labelled mirror games count once as games and
  twice as seats. The input-byte digest pins records; it does not verify
  policy, code or world.
- `arena/greedy_v2.py::ScriptedGreedyV2Player` (`scripted_greedy_v2`): harmful
  table entries pick an opponent-side offer, beneficial ones own-side, declines
  over self-harm when allowed; otherwise v1. Stack spells use a policy-local
  card-ownership proxy. Study label `greedy_v2`.

### This slice — v2 through the monitor/arena path

- `MonitorProtocol.opponent` gains `"scripted_greedy_v2"`. The field's existing
  `exclude_if` keeps default (`scripted_greedy`) protocol bytes and digests

Cohort (all deal seeds fresh, disjoint from monitoring and MTG-137 families):

- **A. Targeting + v1/v2 strength (Study recorder, no checkpoints).** greedy
  vs random and greedy_v2 vs random, plus greedy vs greedy_v2; 25 deals × 8
  legs each = 600 games. Outputs the targeting table by card, cell and seat,
  and v2's head-to-head per cell.
- **B. Headroom (monitor evaluation, paired).** Checkpoints: initialization,
  Mini 12261 at 2k and 5k, Mini 10k ×3 seeds, GPU 12261 at 10k and 25k (only

  cell. 8 × 2 × 400 = 6,400 games.
- Random is not rerun; MTG-137 already holds it as the diagnostic floor.

Analysis: per-cell score with 10,000-replicate whole-deal bootstrap intervals;
paired v2−v1 per checkpoint and cell; seed spread across the three Mini 10k
seeds reported separately from game uncertainty.

**Predeclared (exploratory, commit before scoring):** v2 lowers the mean
Mini-10k score in AvL and LvL (greedy plays Lessons) by ≥ 10 points each; LvA
moves < 5 points. Kill: if v2 moves no cell by ≥ 5 points, targeting is not
the saturation driver and v2 is not recommended on strength grounds.

**Saturation rule (question c).** An anchor is *usable* in a cell when the
strongest retained checkpoint scores ≤ 0.85 with upper bound < 0.95 **and**
the initialization → Mini-10k paired change has an interval excluding 0. It
is *saturated* when the strongest checkpoint's lower bound ≥ 0.85, and a
*floor* when initialization already scores ≥ 0.85. MTG-118 needs every cell
usable on at least one rung.

**Conditional rung (only if v2 saturates any cell).** Add a fixed opponent from
outside the scored cohort: either a frozen checkpoint opponent (needs a
checkpoint `opponent` in `MonitorProtocol`; anchor seed excluded from
scored seeds) or flat-MC search at small N (`demo_search` sims 4–16). Choose by
cost per game measured in cohort A/B; plan and quote it separately.

### Cost (to quote before launch)

A ≈ 600 scripted/random games, B ≈ 6,400 policy games. At ≤ 9 s/game: A ≤ 1.5 h,
B ≤ 16 CPU-hours, about 4 h wall at 4 concurrent single-thread evaluators.
On a rented CPU pod via Etude at roughly $0.10–0.30/h per 4 vCPU, B is under
$5 including setup. On the Mini it fits about 5 h once MTG-137 settles. A is a
small check; B needs explicit authorization of machine and cap.

## Alternatives considered

- **Frozen trained checkpoint as the primary anchor.** Strong and
  self-calibrating, but tied to the current recipe, so future recipe changes
  move the yardstick's meaning; mirror effects with the scored lineage. Kept as
  the conditional rung, not first.
- **Flat-MC search at small N.** Tunable strength (exp-02: N=16 beats random
  91.7%), but slower per game and cannot play control (exp-09), so it may
  mis-anchor Lessons cells. Conditional rung.
- **Edit v1 in place.** Forbidden: breaks frozen evidence and identities.

## Exclusions

No training. No change to MTG-137's protocol, deals or results. No promotion of
an MTG-118 baseline (MTG-118 owns that). No Wave memory edits; the intelligence
Wave's GOAL.md/MEMORY.md are absent in this checkout.

## Forbidden outcomes

Edits to `arena/players.py` or v1 behavior; a second v2 implementation for the
arena; reusing MTG-137 v1 rows unpaired against new v2 rows; dropping missing
checkpoints or unfinished games from tables; selecting checkpoints after
seeing scores.
