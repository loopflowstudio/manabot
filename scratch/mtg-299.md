# MTG-299: policy input validation moves to admission

## Contract (built)

- `manabot.model.admission.admit_observation(agent, obs) -> AdmittedObservation`
  runs every check the forward used to run, in forward order, same exception
  types and messages. Per-schema checks live beside their encoders
  (`admit_facts`, `admit_shared_effects`, `admit_relations`,
  `admit_recent_events`, `NameCandidateEncoder.admit`,
  `SemanticCardEncoder.require_record_*`); admission.py orchestrates.
- `AdmittedObservation(dict)` carries `binding` (ModelConfig json +
  observation config json), checked `references` (CardReferences) and `legal`
  (every row has a legal action; `get_action_and_value` raises
  "No valid actions available" from it).
- `forward`, `forward_distribution`, `get_action_and_value`, `get_value` are
  annotated `AdmittedObservation`. Forward raises `TypeError` on a plain dict, `ValueError` on a binding from a
  different configuration. `PreparedObservation` subclasses
  `AdmittedObservation`; `PolicyInference.prepare` admits then
  `transfer_admitted`. `admit_on_device(agent, obs)` = admit CPU + move.
- Learner: `AdmittedRollout(agent, batch)` admits bootstrap rows;
  `admit_rows(indexes, chunk)` admits only trained rows in minibatch chunks
  (memory bounded; ~216 KB/row at default capacity); `rows(indexes, device)`
  re-reads via `bind_admitted` (no checks). Epochs add no admission.
- CPU lookup buffers for admission are cached by `numerics.buffer_on`.

## Delete — do not maintain (done)

`objects_checked`, `PolicyInference._lookup`, `_attend_objects(objects_checked=)`,
forward-side checks in actor_critic/facts/shared_effects/continuation/
recent_events/name_candidates/semantic_cards/records, the admissible filter in

## Results

- Bitwise (scratch/bench/capture.py, before at base 92560a1e0): 617 tensors —
  logits, values, every parameter grad (semantic, generic, history, WDL), and
  all parameters after PPO (2 epochs x 2 minibatches) and damped updates —
  0 mismatches.
- Host reads per forward (scratch/bench/host_reads.py; item/__bool__/cpu/
  tolist/nonzero/torch.equal), before -> after:
  semantic collection 82 -> 15, semantic learner 98 -> 14,
  history collection 97 -> 15, history learner 113 -> 14. Remaining reads are
  compaction only: legal-row nonzero, used object/fact columns, fact program
  lengths, shared-effect CSR routing (header/detail/member cpu + tolist),
  packed GRU lengths. `__bool__`/`item`/`torch.equal` during forward: 0
  (asserted by tests/model/test_admission.py).
- Admission work: collection admits once per batch (same checks that ran in
  forward, now outside it). Learning admits each trained row once instead of
  once per epoch; rows dropped by the advantage filter are not admitted.
  Cost of one extra CPU unpack per trained row per update.
- Binding comparison: ~1.8 us per forward.

## Concept review (2026-11-12)

One concept, one entry: an observation is admitted once for a configuration
(`admit_observation`), and every forward caller holds an `AdmittedObservation`
(collection via `PolicyInference.prepare`, one-off callers via
`admit_on_device`, learning via `AdmittedRollout`). `bind_admitted` is the only
unchecked constructor and has one caller (`AdmittedRollout.rows`). No design
change and no open product choice.
