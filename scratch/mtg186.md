  both places, keep `RUST_TOOLCHAIN` as the one owner. No behaviour change;
  launched jobs' frozen identity is unaffected (evidence, not rebuilt).

- Rows reuse grid `GameRow` (`heuristic_deck` = MTG-181's deck). Published
  evidence is frozen and the module docstring states the mapping; report and
  summary.json already use mtg186/mtg181 names. Do not rename.
- Per-pairing jobs + `follow` loop vs the experiment-file `eval(state)` shape:
  Jack Heart's steer ("each pairing runs as soon as both checkpoints exist")
  directs this; `etude eval FILE` is still proposed. Keep.
- `_legs` cross-module import already has precedent on main
  (`elemental_long_eval.py`); grid file stays at main's bytes.

not this Task's scope): stock RunPod image lacks Rust (TrainingJob setup
