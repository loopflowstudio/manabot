## Current implementation

- `experiments/tla_pools.py::derive_pools` reparses retained source text before
  admission, preserves event identity and 41-card references, removes basics
  from pools, and saves explicit split membership and provenance.
  `manabot/training/pools.py::PoolCorpus.read` validates the saved partition,
  reference legality and current-world identity. The published corpus contains
  922 entries (827 training, 95 held out) and provenance for 78 excluded events
  and their 41 unknown names. It reserves 100 of the full 1,000 source events
  before restricting the split to admitted events, without backfilling.
- `managym/src/format/limited.rs::LimitedRules` owns construction and picking;
  bindings delegate to it. `cards::limited` was removed, with no re-export,
  following comment c17bdb50. Admission and pool counts are checked once per
  choice request; the remaining minimum-size condition determines stop legality.
  The episode cap is separate from full-deck legality.
- `manabot/training/game_results.py::GameResultWriter` journals completed games
  and seals digest-named artifacts. The collector records both population IDs,
  optional build episodes and native seats before resetting. `execute_regime`
  enables this independently of private recovery and seals on success/failure.
- Schema 3 in `manabot/training/regime.py` names models and validates stage
  roles and typed artifact dependencies. `StageDefinition.run` in
  `manabot/training/stages/contract.py` owns the JSON boundary; the executor
  owns models, provenance and checkpoints. Arbitrary named-model fallback and
  duplicate JSON handling are gone. Self-play resolves its declared model;
  run-wide validation uses `TrainingRegime.model_configs`.

Schema 3 supports module and self-play stages. Producer/learning-state imports
and belief remain single-agent; named-model process recovery is unsupported.
Existing self-play and belief execution remain in place. These limits do not
replace the two-model/module-stage acceptance proof.

## Concept review — 2026-11-11

Outcome for loop-or-next: nothing to change and no open product choice; advance.
Keep the experience in `docs/deck-building.md`: restore a frozen population,
ask the native rules for the next pick or stop, join completed games to both
entries and optional build episodes, and execute stages with explicit model
roles. The review page is `scratch/concept-review.html`. No runtime code or
public contract changed in this review.

The biggest conceptual trap is treating an outcome as an optimizer sample or
a recovery attempt. Preserve one row per completed native game even when both
seats learn or a later update fails. Stage/attempt scope must accompany its
stream/game ordinals; replayed attempts cannot be concatenated as independent
games. A result is retained evidence, not permission to resume a named-model
run. The normal path, optimizer-exception path and existing restore guidance
fit that distinction; abrupt process death is not the same as handled failure
and does not promise an automatically sealed journal.

Counterexamples retained for the next review: identical decks from two events
must remain two pool comparisons; a 41-card reference must not become a
40-card list; a legal 61-card deck may exceed a 60-pick episode; adding the TLE
exclusions must not move existing split assignments; mutating a frozen module
reader must not mutate its run-owned model. These require the current distinct
identities and authorities, rather than another shared lifecycle. The next
evidence is the outstanding gate validation above, not a builder training run
or a migration of existing stages. No games, training or test suites were run
for this conceptual review; earlier receipts remain earlier receipts.
