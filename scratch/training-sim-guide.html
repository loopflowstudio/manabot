01 · CURRENT

Follow a real training run.

Start with uv run manabot train --out .runs/example. The CLI selects the packaged local smoke recipe. That recipe resolves a TrainingRegime and calls execute_regime; it does not contain another training algorithm.

1 · Declare the runrecipes/local.py → TrainingRegime
model, matchup, stages and limits
2 · Collect decisionsSeatRoutedCollector
games → same-player trajectories
3 · Update the modelLearner + update_iteration
PPO or damped-policy objective
4 · Retain resultsTrainingRun + VerifyStore
policy exports, metrics, recovery

The baseline command adds isolated execution and checkpoint evaluation through run_experiment. Etude jobs call the same regime executor while Etude owns placement and attempt identity. These are orchestration choices, not separate RL optimizers.

The other supported path: search → examples → fit

training/execution.py dispatches CollectSearch or CollectLocalUpdate, retains datasets, then dispatches TrainSupervised to training/supervised.py · train_search_supervised. The current regime branch supplies value_weight=0; the fitting API itself also supports joint policy/value supervision. This is offline supervision, with whole-game validation partitions, not on-policy credit assignment.

Compound-policy and belief-sampler stages also have explicit current experiment recipes. They have different data and model contracts; sharing a directory should not pretend their losses are interchangeable. experiments/compound_decisions.py · experiments/belief_sampler.py

No new Executor class is needed: execute_regime already names an action with a clear input and result. Config names describe settings; record and algorithm names describe domain objects. Serialized agent/hypers keys are retained data contracts, not a reason to reintroduce Python aliases.

03 · FINDINGS

The places where the boundary is wrong.

1. The core RL collector is under sim.

sim/net_opponent.py · SeatRoutedCollector contains on-policy batches, return routing, collection snapshots and game-error accounting. It imports training matchups, self-play counters and failure policy. The regime executor and learning diagnostic call it. Its current filename describes one opponent arrangement rather than its architectural role.

Proposed: move the collector and its training-specific batch/snapshot types to training/collection.py. Keep general batched game inference in sim. Place CPU stream producers beside the collector if their only maintained consumer remains that collector.

2. Two fitting loops still live in sim.

sim/distill.py · train_bc performs Adam updates for behavioral cloning. sim/value.py · train_value fits a scalar value head. Their only non-test call sites found in manabot/, experiments/ and scripts/ are in scripts/exp10_value_gate.py; the maintained regime path uses training/supervised.py.

Proposed: retire these standalone experiment-era fitting entry points unless the exp-10 recipe is still supported. If it is, consolidate them through an explicit supervised contract in training, preserving its target semantics. Moving two loops unchanged would leave the underlying duplication.

A direct replacement is not yet justified: old value fitting uses scalar BCE logits and optional encoder freezing; current joint supervision has its own value-target semantics. BC also reports freshest-round validation. Either preserve required behavior with evidence or intentionally retire it—do not silently translate it.

3. Checkpoint I/O is named after its first callers.

General model admission is sim/flat_mc.py · load_checkpoint_agent; generic policy export is sim/distill.py · save_bc_checkpoint. The arena, catalog and regime executor depend on them. Loading a model should not require learning which search algorithm or distillation experiment first used it.

Proposed: model/checkpoint.py owns portable model save/load and world/ABI admission. Training retains optimizer/collector recovery and run-artifact admission. A playable checkpoint remains different from a resumable update snapshot.

4. Dataset generation, schema and fitting share distill.py.

The file currently owns game generation, shard loading, whole-game splitting, target helpers, old fitting and checkpoint saving. The new supervised module still imports its data helpers. Separate the retained dataset contract from search execution and from loss code; avoid another file named for a teacher generation.

Proposed: training data/schema and validation partitions in training/data.py; search target generation in sim/data.py; fitting in training/supervised.py. Move only consumed helpers, with the target/provenance fields explicit.

5. Shared provenance is hidden in teacher1_evidence.py.

sim/teacher1_evidence.py · runtime_fingerprints and source hashing are used by training execution and scheduling. The same module also records and replays a particular teacher study. Extract shared runtime identity to infra; keep historical teacher receipts and their identifiers intact.

One apparent mismatch that is not training

sim/local_update.py · LocalUpdateTeacher holds a frozen policy and estimates root-action values. regularized_update computes a root action distribution; it does not optimize model weights. Its natural home is search/simulation. Naming it by frozen-policy search would clarify that distinction.

04 · PROPOSAL

Group by architecture, not by experiment generation.

The current training folder has 49 Python modules. It is also the home of schedulers, report rendering, notebooks and tracker delivery. The first useful split follows lifetime and authority: fitting one run, scheduling runs, evaluating checkpoints, and reading evidence.

Proposed ownerResponsibilities and current source families
model/ActorCritic, model construction/inference, portable checkpoint serialization and admission.
training/Regime execution and state; collection; learner; PPO/damped/supervised/compound learning; training data; health; recovery. Keep this initially flat rather than creating a package for every small module.
sim/Players, batched games, search backends, frozen-policy search, target generation. Separate algorithms by their current contracts, not teacher-0/1 or exp-N names.
recipes/Packaged baseline/local/Ataraxos choices and recipe builders. Repository experiments/ keeps authored comparisons and historical evidence.
experiment/The Manabot Experiment schema, local scheduler, Etude job adapter, execution receipts and source binding. It describes/launches Manabot work through Etude; it does not replace Etude.
evaluation/ or existing arena/Checkpoint protocols, bounded monitoring queue and head-to-head evaluation. Choose the destination around the existing arena API, preserving monitoring vs scientific holdout distinctions.
reports/Read-only analysis, dashboards, time profiles, cohort views, notebook templates and retained-study readers. A reporting module must not own learning or retry policy.
infra/Runtime context, clocks, atomic persistence and source/native fingerprints when truly shared. Avoid a miscellaneous system.py.

This is a responsibility map, not an approved directory migration. Start with the clear ownership fixes; create sibling packages only when their public boundary is concrete. The current local scheduler is used by the baseline recipe, so it cannot be deleted merely because an Etude path also exists.

Proposed contributor guidance

To change what a run does, edit a recipe or experiment. To change how a batch learns, edit training. To change how a frozen policy chooses a move or generates a search target, edit sim. To change the network or portable model format, edit model. Scheduling, evaluation and reports consume the run contract; they do not introduce another learning loop.

Preserve one learner for PPO/damped updates. Keep supervised and compound update contracts explicit where sample structures differ. PairedLearners currently has no non-test caller in the scanned product/recipe/script tree; audit whether that is a supported capability before carrying another orchestration abstraction into the new layout.

05 · INVARIANTS

A simpler layout must preserve recoverable state.

A file move is safe only if the same run still means the same thing. The normal route exports an admitted model and a durable run record. A failed game or process has additional state that must not be collapsed into that export.

EventOwner and required behavior
Successful updateTraining owns model/Adam/EMA clocks and collector state. Model export can serve inference; update snapshots can serve admitted continuation.
Game failureStrict mode stops with retained private evidence. Opt-in tolerance discards the failed game’s rows and regathers under the existing error allowance.
ResumeRestore committed learning and collection state; reapply durable failure ledger. Do not erase costs, prior failures, identity checks or original deadlines.
Evaluate / reportEvaluate immutable checkpoint identity under the declared protocol; reports read retained evidence. Monitoring observations do not become scientific holdout results.

The excerpt shows an actual admission boundary: source repair requires a parent, reason and complete-game error policy. Relocating modules changes source fingerprints; old exact-resume identities must not be silently accepted. Historical recipes and receipts retain their bytes and use pinned source when their executable contract is retired.

Next proof for an accepted layout: replay the local recipe; verify same-player credit and one/both-seat boundaries; round-trip exported models; compare uninterrupted and resumed state; verify supervised target/partition semantics; build the wheel; test dependencies so sim does not import training orchestration.

07 · REVIEW

Decide what deserves a maintained path.

The most consequential choice is the maintained surface, before directory names. I recommend retaining the regime-based RL and search-supervised paths, and retiring the exp-10 standalone BC/value fitting entry points unless you still use that workflow. Preserve its results and pinned source. Do not carry separate loops forward just to make the new folder tree resemble the old one.

Then make the clear moves: collector into training; portable checkpoint I/O into model; dataset contracts apart from search and fitting. Group scheduling, evaluation and reports after those ownership boundaries are explicit.

Open for discussion: is the exp-10 BC → value-only fitting workflow still part of supported training, or should it become historical-only? Repository callers establish where it is wired, not whether an external research workflow still relies on it.

This guide does not claim production usage telemetry or CUDA validation. The supporting cleanup has CPU tests, native-backed local execution and a full CPU learnability diagnostic; those do not prove equal learning value between one- and two-seat training or full-game strength.
