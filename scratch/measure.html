### Concrete hypotheses and ceilings for optimize-plan

First candidate: eliminate reserialization of **already-built JSON Value arrays**
inside `Observation::to_json` (`managym/src/agent/observation.rs:2066`).
`action_json`, card arrays, stack objects and recent-event arrays are built as
Values and fed through `json!` again. The locked serde_json 1.0.150 macro calls
`to_value(&$other)`; its Value serializer creates owned strings/maps/vectors
again. Instead, assemble those existing subtrees once and move `Value::Array`
into the final object/action-space map. Keep ordinary typed-field serialization,
the same final sorted map, and the existing final string serializer. This is a
bounded ownership change, with no persistent cache or hash substitution.

This redundant construction is identified in the measured hot owner, but timers
do not isolate its fraction from necessary construction. It may be too small to
clear latency noise. The **entire** measured build+drop category is only an upper
bound: 21.99–23.75% of the instrumented full search, so impossible complete removal
gives at most 1.312x there (T/(T-x), maximum over the five runs). Halving that
whole category would yield only about 1.124–1.135x in those profiles. This
is a ceiling for that measured work, not a strict bound on every serializer
rewrite: unseparated cleanup is outside the category. Neither is
an ordinary-wheel prediction or a promised saving from moving arrays.
Keep the simpler experiment only if byte equivalence holds and a new ordinary
five-pair comparison clears noise; otherwise restore the last kept baseline.

A broader second hypothesis is direct borrowed serialization of the complete
observation, avoiding the intermediate Value tree. It shares the same measured
materialization ceiling, but adds key-order/omission/enum/float compatibility
risk and more code. Prefer the bounded subtree move first. Do not implement
either in this baseline step. Exact canonical bytes remain the authority: no
witness BLAKE3/SHA-256 substitution, schema changes, reduced viewer content,
event suppression, audit opt-out, relaxed Commands or checkpoint rebinding.

Authority Value construction is smaller (4.19–4.42% of full profile; impossible
complete-removal ceiling 1.0463x, excluding unseparated destruction). Direct
serialization must preserve the existing sorted nested match-state keys, so it
is not a free `to_value`→`to_vec` substitution. Deprioritize it for now.
Rules execution is at most 1.90% (full-removal ceiling 1.0194x), acting byte
clones below 0.057% (1.0006x), audit-record writing below 0.456% (1.0046x).
Those are poor targets, and required rules/audit work cannot simply disappear.
Even impossible removal of witness JSON alone (excluding the semantic path)
would yield at most 1.303x in these profiles. None of these bounds closes the original near-singleton gap.
