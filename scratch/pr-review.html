01 · Runs without a new setting

Collection owns a temporary inference cache

Call SeatRoutedCollector.collect(agent, num_steps) as before. It still returns a rollout batch, but now owns one PolicyInference scope shared by learner and live self-play inference. CPU observation checks precede device transfer; semantic catalog encodings can be reused within that scope.

Ownership boundary: leaving collection clears the cached catalog, including on an exception. A later collection creates a fresh scope. Within a scope, changed weights or model mode cause an error instead of reusing stale state.

Follow the prepared input into Agent; inspect the parity test

The normal tensor-dictionary path still computes fresh differentiable embeddings. The test compares exact outputs and subsequent gradients on CPU; it does not establish ordinary CUDA repeatability.

The acceptance mismatch is in the retained evidence

All 1,152 actor results matched, but the large whole-training gain was only 0.82%; tiny Adam differences and differences among reference repetitions left the exact gate failed. A reviewer can assess the cache contract separately from the choice to require exact GPU state. No revised acceptance criterion is recorded here.

02 · Also changes ordinary runs

Step environments without copying every deck setup

The same vector step now borrows each stream’s immutable configuration while mutating its environment and seed. Inactive streams still skip stepping. This removes work on every micro-step without changing the reset input or returned observations.

Review focus: configurations remain owned by the vector between resets. This is ordinary Rust field borrowing, with no new unsafe code in this diff. The new masked, mixed-deck test compares vector stepping and autoreset against individual environments.

Native proof and measured limits

Run022 measured 1.2705× complete-training throughput for four borrowing producers versus one cloning producer at 4,096 streams. It combines two changes. The ordinary exact-state gate still failed; baseline controls varied too.

03 · A recipe opts in

More producers; one owner of policy and rollout order

A self-play stage can set execution.workers to 2 or 4. The default stays 1. Native environment work is split across persistent threads; policy inference, action sampling and learning stay with the caller. The API remains synchronous: each step waits for all shards.

Failure and recovery: a worker error settles all submitted writers, then closes the pool and raises. Partial output is not a checkpoint. Recovery uses the existing saved update state and a fresh collector; native actions are replayed and buffers checked before learning resumes. A hung native call still needs the existing outer process deadline.

Trace recovery and cleanup through the real contracts

The test runs serial and four-worker training, interrupts a run, resumes it through execute_regime(..., resume_from=failed.id), and compares learner/optimizer/EMA/RNG and collector state. Production stage execution registers collector.close with its resource stack. Live continuation now requires the same worker count.

04 · Read existing evidence

Pick runs and inspect where training time went

The new CLI discovers saved native and Etude runs, then writes an offline picker, phase flamegraph and attempt timeline plus a JSON snapshot. It never starts training. Parallel evaluation accounting remains outside this delivery.

The model distinguishes a run from an attempt. One logical run owns member IDs, attempt intervals, phase coverage and source references. Unknown time remains nullable; missing or branching lineage cannot become invented progress.

Selecting a checkbox updates the aggregate and timeline together. Phase totals are duration-weighted; comparable throughput is pooled by recipe and hardware. The report does not turn host intervals into GPU utilization or claim a complete historical inventory.

Selection, source failure, and how the caller continues

A bad source produces a visible coverage warning. With zero discovered runs the CLI still writes the diagnostic report, then exits 1. Correct the source path and rerun the successful command above; no training state was changed.
