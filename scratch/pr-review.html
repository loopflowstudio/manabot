1. An isolated crash can stop costing the whole run

Add game_errors to a new, single-stage self-play recipe to opt into replacement games. Without it, execution still fails strictly; capture is now automatic. Frozen recipes omit the new field from their serialized identity.

Accepted: stop strictly above 10%. Engineering choice: a 100-game rolling window and 100-game warmup. The denominator is settled games, not seats or transitions. Truncation, action limit and deadline are failed outcomes; deadline expiry still stops immediately.

Inspected proof: test_strict_threshold_window_and_restart exercises warmup, 10/100, 11/100 and ledger reconstruction. The 57-test result is recorded by the implementation worker; this review does not rerun it.

2. Throw out this game’s two seats, then refill

The tolerant collector uses per-stream native outcomes. A failed row is settled before replacement; successful rows in the same vector call keep their progress. The current game’s finalized samples and pending decision are removed from each of its learning seats.

The consequential tradeoff: opted-in one-seat collection now finishes games before updating. No portion of a later-crashed game has already trained the model, but batch size and update timing differ from the old one-seat quota path. Both-seat collection already had this boundary.

Complete-game entry and replacement order
Native isolation preserves successful rows; setup and encoding remain fatal

Inspected proof: native isolated_failure_preserves_successful_streams_and_seed_stride compares surviving rows to a control vector and checks replacement seed succession. Collector tests cover both-seat quarantine, bounded all-failure stopping and preservation of earlier completed games.

3. Learning rolls back to a commit; failure allowance does not

A repaired run resumes the committed learner, optimizer and RNG snapshot. Failure receipts written after that snapshot still count: ancestor ledgers are replayed separately, and the child appends to a new private ledger. A restart cannot erase an exhausted allowance.

Boundary: local CPU process recovery also requires the existing current-game snapshot policy. Game-level regather on a GPU does not establish portable CUDA optimizer/RNG restart. Receipt write failure stops recovery rather than granting unrecorded retries.

Inspected proof: test_repaired_restart_preserves_post_snapshot_failures_and_costs uses the real local store, recovery and accounting owners with a fake provider/evaluator and CPU placement. It checks one reconciled provider claim, retained deadlines/reservations, checkpoint deduplication and unchanged original evidence—not a paid or production-provider run.

4. Replay explains agreement, not just “failed again”

A different offer at the same index is a binding mismatch. A different exception there is a new failure. Successful execution after repair does not change the original attempt, counters or evaluation result.

Review correction, now implemented: the earlier local implementation treated action position as sufficient evidence. This snapshot checks a retained frame before execution and compares error class/message separately. Missing older metadata produces null; it cannot silently count as agreement.

Comparison and runtime admission

Evidence limit: the payment regression uses native Mountain/Gray Ogre games with a faulty fixture payment validator and its repair. The original Gnarled Professor game cannot be reproduced from the supplied seed alone: its 34-action prefix is unavailable. Runtime hashes identify bytes; they do not archive those bytes.

5. Strict failures now leave evidence, while evaluations stay strict

Ordinary scalar/vector consumers keep raising the original error, but now retain private replay inputs. Arena goes further: the parent fsyncs the pending Command and acknowledges it before the worker enters native execution. A killed or timed-out worker cannot make an unobserved action look completed.

Strict scalar caller: retain evidence, then propagate

Different evidence, different promise: scalar/vector positional prefixes remain in memory until a caught failure; hard aborts and hangs still need external supervision. Arena and semantic Command journals retain pre-execution inputs. A strict vector error leaves individual row outcomes unknown, even if later replay succeeds.

Private strict-capture data model

What an operator sees in the report

Public summaries expose completed/crashed counts, discarded/replacement samples, the measured window and stop reason. Raw exceptions, seeds, decks and frames stay in private artifacts. Incomplete evaluation cohorts still receive no loss, draw or strength score.

What this walkthrough establishes

The code supports an opt-in training tolerance policy, automatic strict capture, immutable local diagnostics and explicit compatible-source continuation. It does not establish repaired game rules, unbiased strength, portable CUDA restart or hard-abort capture on every native path.
