A payable action must have an executable payment.

Activating Prophetic Prism with a Treasure and an empty pool used to be offered, then fail with illegal mana activation. The repair makes affordability and execution use the same resource model while keeping mana colors as player decisions.

Representative tested interaction
Activate Prism → activate Treasure to fund its upfront cost → choose Treasure color → pay Prism’s cost → choose Prism color → return to the spell payment or priority.

1. Feasibility returns a witness, not a separate promise.

The old grouped boolean search and fixed-only activation planner could disagree. The new model owns source identities, exact pool remainders, life, and ordered obligations. A witness includes automatic steps and visible actions; finding a color in a witness does not choose that color for the player.

2. Announcing a filter opens its own payment.

The same activation witness is consulted for the offer and execution. The ability’s source is reserved for incompatible uses before searching its upfront payment; its output comes after that payment. The original payment stays in the obligation chain.

3. Nesting preserves the original decision.

ManaUpfront carries an explicit continuation in the existing effect frame. Automatic prefixes commit exact spending; color selection remains an offered action. After selecting a nested color, execution resumes the enclosing payment rather than losing its target, payer, or effect.

4. The regression and its recovery boundaries.

The original counterexample now reaches both color decisions. Other directed cases check seedless filter cycles, restricted mana, tap versus sacrifice reservations, waterbend bonuses, life costs, and optional continuations. Tiny decision trees execute every offered branch, replay their action prefixes, and roll back exact state.

Vector failures now retain private reset inputs, seed, successful action prefix, and attempted action. The snapshot can reflect partial mutation, so recovery reconstructs the pre-action root from those inputs; the snapshot alone is not an undo guarantee.
