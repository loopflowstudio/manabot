01

A recipe is an entry point, not a trainer.

The bare command now runs local-smoke-v1: two CPU updates using the production model, collector and learning rule. Completion prints a loadable policy checkpoint. This intentionally replaces the old fixed-seat PPO preset; it does not reproduce that preset’s training semantics.

The CLI chooses this recipe when no recipe or regime is specified. One-seat mode uses exact quotas; both-seat mode finishes games and treats the row target as a floor. The 120-second deadline means failure, not a shortened successful schedule.

CLI failure and migration boundary

Observed rejection: uv run --no-sync manabot train --preset default exits 2 with “training --preset/--set are retired”. Choose --recipe local, --recipe baseline, or current --regime JSON. Old reward/optimizer flags are not silently translated. Baseline owns independent evaluation; local smoke does not.

02

A model, its learning state, and orchestration.

There are distinct responsibilities, not four synonyms for the same network. The actor/critic is shared by RL, supervised fitting and inference; the learner adds optimization state. The regime function sequences work without adding an Executor object.

NameMeaning in this change
ActorCriticThe PyTorch model: shared observation encoder, actor logits and scalar/WDL critic.
LearnerOne trainable model and Adam state. Learning-rule functions perform updates; no environment or independent loop.
ModelConfig / ModelOverrideConstruction settings / an experiment’s explicit override. Neither is another network.
SeatRoutedCollectorGames and same-player trajectories. It owns sampling and seat routing.
execute_regimeA function coordinating stages, clocks, artifacts and recovery.

The old Trainer tied the model to an environment, tracking object and training hyperparameter bundle. The replacement explicitly restores train mode after checkpoint admission and retains Adam’s epsilon and initial rate; the selected learning rule supplies each update’s rate.

Independent evidence for credit ownership

Recorded CPU checks include hand-calculated asymmetric A/A/B/A/B trajectories, swapped seats, draw/reset boundaries, and actual actor/critic gradients. This demonstrates tested ownership boundaries; it does not establish equal learning value per decision or full-game strength.

03

Runtime setup is not an experiment definition.

Experiment now means the authored comparison: baseline, cases, matrix and jobs. RunContext owns per-run setup and Etude tracking. Configuration objects consistently use Config; there are no old Python aliases.

The unused full-Hypers fallback and W&B switches are removed. Seed timing and Etude’s launched-run identity remain. The simulation caller now closes the runtime context as well. Checkpoint dictionaries retain their existing wire keys; those strings are data format, not live configuration types.

The other Experiment is an authoring model

Runtime recording, failure settlement and launcher-directory behavior are exercised by tests/training/test_etude_sdk.py.

04

One current input contract, without a translation layer.

Current recipes use damped_policy. Following your review direction, old ataraxos_move input is rejected rather than translated and re-serialized under its original tag. The frozen historical JSON remains evidence; its executable loader has been removed.

This is a deliberate support boundary: a frozen old-tag recipe needs its pinned source. Editing it to a current recipe creates a different identity and does not authorize resuming the old run. Ataraxos remains a legitimate experiment/builder name; there is one descriptive runtime learning rule.

What changed after the first published version

The initial PR head 6e33e0f4f included LearningInput. The current head deletes that decoder and its serialization override, retires the old preset loader, and gives current examples a fresh recipe in recipes/ataraxos.py. Frozen file bytes are unchanged.

05

Search produces examples; training fits the model.

Search-based supervised learning remains supported. Its fitting and evaluation implementation moves from sim/search_supervised.py to training/supervised.py. Search data generation remains a separate consumer/provider boundary; PPO and damped-policy updates are not involved in this fit.

The function owns its supervised Adam state, target selection and whole-game validation split. The executor supplies the dataset and receives the fitted model, metrics and epoch history. This separation preserves meaningful algorithm differences rather than inventing a universal trainer wrapper.

Supervised proof and scope

The moved suite tests policy-only versus joint gradients, score/visit targets, declared observation shape, continuation and checkpoint reload. The algorithm is unchanged. Older BC/value fitting loops remain in sim; the companion training/sim guide identifies those and proposes the next ownership changes.

06

The same continuation contract, with explicit owners.

A policy export is still not a resumable training snapshot. Recovery saves the learner and collector explicitly, restores both, and then reapplies the durable game-error ledger. This PR changes ownership plumbing; the bounded recovery behavior was supplied by the base revision.

Without tolerance, a caught game failure stops training and retains private evidence. Opt-in tolerance discards the failed game’s rows and regathers; it also finishes complete games in one-seat mode. Restoring Adam cannot erase failed attempts, prior costs or the applicable original deadline.

Keep the parent’s recipe, seed, cadence and allocation arguments. Source repair needs an explicit reason and an admitted complete-game error policy; it does not waive world, content or input compatibility. The local smoke recipe does not implicitly enable this recovery contract.

Validation and limits

Validation is recorded in the accompanying task notes.
