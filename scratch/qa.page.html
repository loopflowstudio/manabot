Fixed here

A checkpoint written by manabot/recipes/local.py (or baseline) on base, one revision before this branch, failed at HEAD with size mismatch for semantic_cards.record_name_keys: 3410 vs 1800. The decision-memory one failed with record_token_rows 3393 vs 3349. Academy listed both as available, so the failure only showed when a game started.

Cause: model_interface returns None for exact-deck bindings, so admit_checkpoint never bound by key. The pinned pilots and the constructed test only covered world bindings.

Fix: bind_records checks that the stored card programs equal the running pack's, then rebinds record and token rows by key through the same rebind that bind_catalog now uses. The existing retirement test is now parametrized over world and exact-deck bindings. Its exact-deck case fails without the fix.
