Fixed

Every refused replay left an empty --output-dir behind, so rerunning the corrected command failed with "exists". Replay now loads the policy and admits the first captured call before creating the directory; the empty-replay check moved there with it.

The smoke test now calls replay with the wrong checkpoint and asserts no directory remains. It fails without the fix and passes with it.

What works, what wasn't reached, what's still rough

  • Works: capture, replay (CPU, MPS, every variant MPS allows), grid cross-width binding, report rendering of fresh and recorded receipts, the arena runner's forward records.
  • Not reached: CUDA replay, peak-memory and kernel attribution, and tf32. Those need an L4 rental, and the recorded L4 receipts already cover them.
  • Still rough (minor, left): bf16-on-CPU and corrupt capture files end in tracebacks rather than argparse errors; capture --help lists --deals as 32 separate choices. The bf16 arm reports exact_bf16_logits: true against itself, which is accurate but empty information.
