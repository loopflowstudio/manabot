# MTG-273 — bounded self-play outcome logging

## Outcome

Remove the reproduced matchup-metric index amplification while preserving every
completed game's deck, opposing deck, play/draw position and win/loss/draw count.
Keep policies, sampling, recovery allowance, frozen configurations and evidence
unchanged. The training metric row carries a table digest; Etude carries the
immutable JSON row table. Offline readers verify it and expose the established
flat reporting projection after selecting the winning update/attempt.

## Delete — do not maintain

- Removed live `self_play_outcomes` lists from UpdateDiagnostics and their
  flattening in the executor, including the live writer's deck-hash metric names.
- Removed the reader's cached whole-block history and all-attempt row lists.
  `update_metrics._updates` decodes one block at a time, replaces duplicate rows
  by update, and applies resume cutoffs in chronological attempt order.
- Preserve SelfPlayCounter and snapshot semantics, exact counts, ordinary
  update clocks, all stored historical metric bytes and report behavior.
- Retain keyed-list flattening for historical StageRecord diagnostics and the
  offline table projection; this is reader compatibility, not a live writer.

## Implementation and checks

1. Save bounded per-update row tables under the run's immutable artifacts tree;
   publish a verified digest reference through the ordinary update metric row.
2. Resolve selected references through their metric block's Storage, preserving
   moved runs, later attempts and historical rows. Missing/corrupt referenced
   tables fail visibly; unselected tables do not become outcomes.
3. Check exact roundtrip, shipping, resume replacement, historical mixed reads,
   and bounded actual-SDK manifest work with a small fixture. Record measured
   before/after results separately from unmeasured long-run CUDA acceptance.

Implemented: per-update immutable tables, one metric digest, selected-table
verification and historical reporting projection. A newly exposed consumer
failure (the reference shared the count namespace) was fixed by consuming the
reference during projection; the ordinary executor test then passed. Empty
resumed attempts now cut off stale updates even before writing a new row.

Compression keeps only one attempt's candidate rows alongside selected history,
with block provenance attached until the final table projection. Missing attempt
metadata uses the block's start time, matching Etude's ordering. The temporary
file context owns failed-write cleanup; `.partial`, fsync, atomic rename and
digest verification remain. No further deletion targets remain in this cut.
