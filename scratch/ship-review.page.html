Cut game-side host, replay, and heuristic-stepping overhead in vectorized eval

MTG-506 · PR #643 · 598663ae16 · stacked on PR #638 (MTG-497)

Vector evaluation against the built-in heuristic now steps heuristic turns natively in Rust, drops per-decision viewer projection, and runs single-digest replay on two background threads — raising M4 Max MPS throughput 6.0× to 11,959 games/hr with forwards at 85% of wall time.

1. What was built

When you run a vectorized evaluation against the built-in heuristic, the engine settles every heuristic turn internally in Rust (heuristic:64) so every live slot in a round contributes a row to the checkpoint forward batch. Finished deals verify and retain evidence on two GIL-releasing background threads while the remaining slots keep stepping. Vector records store compact runner annotations instead of live viewer frames (frames reconstruct on demand from the verified record), and process-constant fingerprints compute once per process. Built-in heuristic declarations must now opt into version: "native-v3" so stored native-v2 tournaments cannot silently mix with the fixed stateful heuristic.

How to try it: uv run --no-sync python -m experiments.eval_throughput --output-dir ".runs/ship-review-$(date +%s)" --device mps --runner vector --slots 64 --deals 4 --checkpoint /tmp/mtg497-local-policy/00002000-raw.safetensors

2. How it works

Per-slot native heuristic seats and version enforcement

PlayerPolicy::Heuristic { max_actions } serializes as heuristic or heuristic:<N>, keeping the existing record string format while honouring the registered 64-action cap. SlotLoad::Fresh carries an optional per-slot policy pair so deals can swap seats across legs without resetting the vector.

Serialized as a plain policy string so GameRecord.player_policies and snapshot replay need no schema bump. Both runners now open one stateful player per game seat via open_game(seed) instead of rebuilding per decision. Vector evaluation seats NativeHeuristic natively in Rust; CodeSeat stays a Python seat. Refuses built-in heuristic players that omit version="native-v3" so stored native-v2 tournaments cannot silently mix.

Compact vector evidence, isolated failures, and background replay

Vector rounds skip live viewer-frame serialization, describe_actions, and decision_observations (except for custom CodeSeat slots). Completed deals hand off to a bounded 2-thread ThreadPoolExecutor, while RecordWalker.run takes a single-digest path for plain integer trajectories and PyEnv releases the GIL during replay.

Vector capture omits live viewer frames, so private_exposures is removed rather than reported as zero. Each leg carries its own (candidate, opponent) native policy pair into SlotLoad.fresh. Completed 4-leg deals verify off the stepping loop; backfill stays open while fewer than slots replays are pending. Native opening or step crashes attribute to game_error_seat rather than the last Python actor. Direct path checks digests[0] once and each post-step transition once, cutting replay state_digest calls in half. PyEnv.reset, step, and state_digest release the GIL so background replay threads run alongside the main loop.

Unified per-slot failure records and process-level fingerprint caching

Isolated reset and step failures share one per-game GameFailure schema hoisted by GameRecord.for_game(). Any stream with game.end.status == "failed" reports original_outcome="failed"; strict batch exceptions stay execution_outcome_unknown. Matched 16-deal profile cut runtime_fingerprints from 1.782 s to 0.027 s across 80 calls.

3. Key data structures and APIs

PlayerPolicy::Heuristic { max_actions: Option<u32> } (player_policy.rs)
Parses and displays agent, random, heuristic, and heuristic:<N>. Enforces the positive u32 action cap inside native heuristic selection.
SlotLoad.fresh(..., player_policies=None) & VectorEnv.reset_each_into_buffers(..., player_policies=None, isolated=False) (managym/__init__.pyi)
Additive public API (recorded in tests/public_api.json). Omitting player_policies uses the vector's default pair, never the previous occupant's. isolated=True converts per-slot construction and opening-settlement errors into poisoned slots and receipts carrying game_error_seat. VectorEnv.current_player_policies() inspects live slot pairs.
GameInputs.player_policies & GameEnd.failure: GameFailure (recording.py)
Multi-slot snapshots and journals store per-game policies (omitted when equal to GameRecord.player_policies) and per-slot isolated failures (operation: "reset" | "step", error_class, traceback). GameRecord.for_game() hoists both to top-level fields when projecting a single stream.
NativeHeuristic, CodeSeat, GamePlayer.open_game(seed) (agents.py, agent.py)
Replaces the old agents.py:Heuristic. Built-in heuristic seats require Code.config["version"] == "native-v3" (HEURISTIC_VERSION), which changes Etude player keys and derived game seeds. Registered custom code players stay CodeSeat and keep stateful per-game instances via open_game(seed).
DecisionIdentity & compact vector annotations (evaluation_records.py)
Vector annotations store actor, revision, player_id, player_seed, player_decision_ordinal, policy_rng_seed, and latency_seconds; they omit frame_sha256, chosen_offer, and action_space_kind. audit_view derives offer IDs from inputs["actions"][i] when chosen_offer is absent; _replay_record verifies optional fields when present.
NativeSeatRecord (watch.py)
Typed refusal raised when Academy Watch or configured launch tries to open a non-("agent", "agent") record, directing the user to uv run python -m managym.replay <file>.

4. Trade-offs and invariants going forward

  • Stateful heuristic changes play (16 / 7,155 decisions in 10 / 64 profiled games). Both runners previously rebuilt the heuristic every decision, dropping intra-turn state (attack pool, block plan, kicker memory). Fixing this aligns eval with training's native heuristic seat and shifts the heuristic identity to native-v3 (including player_policy.rs in heuristic_source_paths()). Existing stored experiment declarations stay unversioned and refuse loudly rather than mixing cohorts.
  • Native heuristic decisions leave the stored record. A vector record against the built-in heuristic holds only the checkpoint's surfaced actions, digests, and annotations. Heuristic turns are recomputed at replay and bound by the next surfaced digest and the final digest. decisions, per-player latency, and max_commands count surfaced checkpoint decisions.
  • Compact vector records trade live viewer hashes for speed. Scalar records keep live viewer frames, frame_sha256, and the per-decision private_exposures check. Vector records omit them because nothing in the vector runner consumes a viewer frame; any frame can still be reconstructed deterministically by walking the verified record.
  • Background replay bounds memory without stalling steps. Two worker threads verify completed deals while up to slots settled matches may be in flight; once at capacity, backfill pauses while retaining the idle vector until a replay finishes. If future workloads ever starve the loop, replay child processes remain the documented fallback.
  • Security & trust boundaries: This diff touches record/provenance caching (@cache on process_fingerprints and arena_source_sha256), untrusted policy-string parsing in Rust (PlayerPolicy::from_str), replay verification of stored records, and removes the per-decision private_exposures viewer check in the vector runner (because no viewer frame is constructed or sent). Worth a quick lf security-review before delivering if you want a formal check on the replay/provenance boundary.

5. Findings left outside this PR

Vector evaluations against the built-in heuristic now record ("agent", "heuristic:64") / ("heuristic:64", "agent"). managym/academy/watch.py refuses any non-("agent", "agent") record with NativeSeatRecord and directs callers to uv run python -m managym.replay <file>. Surfacing or recomputing native-seat turns inside Watch is Academy-scoped work.

tla_trophies*.py, opponent_memory.py, mana_taps.py, and tla_frontier.py remain unversioned on this branch so they refuse loudly instead of silently mixing native-v3 into stored native-v2 tournaments. Choosing new -v3 tournament names (and which baselines to rerun) is irreversible once scored; handle it when starting the next evaluation campaign (Question 1).

Surfaced during QA: ScalarCapture writes ("agent", "agent") even if the wrapped managym.Env was created with player_policies=("agent", "heuristic"), because Env exposes no policy getter, causing replay divergence at index 0. Predates MTG-506; scalar evaluation always seats ("agent", "agent") and vector capture records per-slot pairs accurately. Fixing requires an Env.player_policies Rust getter + public API addition (Question 4).

Owned by stacked parent PR #638 (MTG-497). Locked CI fails on the unreleased etude-sdk 0.5.0 async imports, and editable Etude 1f7496e9 renamed Matches to MatchStream. Once MTG-497 lands with the published SDK, sync MTG-506 onto main before delivering.
