MTG-501 · Guard runtime program tokens against the policy vocabulary

PR #636 · tracks manabot#629 · branch jack/mtg-501-fix-runtime-program-token-vocabulary-mismatch at 68c414a1b6

1. What was built

Every runtime program token stream leaving TokenWriter::into_rules_tokens now panics in debug builds if it emits a non-numeric token outside the vocabulary a default catalog policy (decision_memory=False) admits. Previously, unregistered runtime structs or labels passed unit tests silently and crashed live self-play admission (as GrantClock did in 0.2.6 before commit 8904bf12a5 stopped emitting it).

Turning that guard on immediately surfaced and fixed six latent vocabulary leaks on main without touching the 0.2.x public API or adding a 0.2.6 GrantClock shim:

  • "enters attached to" projection label missing from EXECUTION_TEXT (f35670541f)
  • LoyaltyCost::MinusX, /Modification::AddTypes, /Modification::AddColors, /Modification::ModeChosen, DamageKind::Combat, DamageRecipientFilter::Any, and TriggerCondition::TappedForMana (f35670541f, 5424678db4)
  • Out-of-catalog chosen card names leaking from expanded naming fixtures across SearchNamed, ZoneEntry.chosen, Effect::ExileNamed, and FactKind::ChosenName (5424678db4)
  • Text "all" (CreatureTypes::All) emitted when a stacked object retains a departed changeling's last-known characteristics — caught by QA during a 200-game sweep (b5083bb212)
  • SpendingObject / SpendingContext::Activate (and attached-grant AbilityGrant) leaking into decision-memory snapshots because decision_memory::snapshot copied layers.rs's live view.activated_abilities verbatim — caught by CI (68c414a1b6)

Real guard output when an unregistered token leaks (from QA game 38 before b5083bb212):

runtime program tokens outside the policy vocabulary: (6, 0x43dc8b2f)
  into_rules_tokens ← Projection::finish ← project_stack_object ← Game::stack_frame
  ← continuation_frames ← Observation::for_player_with_events ← Env::step

Real Python admission output when an unknown token is injected into a live observation:

ValueError: policy received a program token outside the vocabulary; missing keys: (6, 0x7abc1234)

How to try it: cd managym && cargo nextest run --profile ci -p managym -E 'test(runtime_token_guard) or test(runtime_only_programs_have_catalog_tokens) or test(activated_ability_snapshot)'

2. How it works

Single vocabulary rule and debug emission guard

PROGRAM_VOCABULARY computes the exact set a default catalog policy (decision_memory=False) admits once per process, and missing_program_tokens replaces four divergent Rust vocabulary checks. TokenWriter::into_rules_tokens calls it in debug builds for every stream built against default_content_pack().

Excludes the 44 DecisionMemory::* rows because default policies strip them from record_token_keys. Only Integer (4) and Boolean (5) bypass lookup; Null (8) and DefinitionRef (7) are checked strictly, matching admission.py. Scoped to default_content_pack() by pointer identity so synthetic test packs do not false-fail, while catalog_tokens() exits through span() and never recurses.

Stripping derived runtime fields from decision-memory snapshots

layers.rs stamps activation pricing context (SpendingContext::Activate / SpendingObject) and attached-grant provenance (AbilityGrant { grantor: ObjectId, .. }) onto live battlefield views. Clearing both when building a PrintedCharacteristics snapshot prevents unregistered tokens and storage IDs from entering definition_tokens() and restores definition_only() deduplication for unmodified permanents with activated abilities.

Resets mana_cost.purpose to the printed default and drops granted_by provenance.

Uniform out-of-catalog chosen-name rule

When an expanded naming fixture lets a player name a card absent from the installed catalog, rules state and human-readable text keep the exact spelling while policy programs encode Null and the permanent encoder omits FactKind::ChosenName.

EntryChoice::CardName and Effect::ExileNamed.name route through StringField::ChosenCardName.

3. Key data structures and APIs

  • Public API (unchanged): managym.catalog_tokens() (printed card spans only) and managym.record_vocabulary() (runtime names and token pairs) keep their exact signatures and return schemas. Docstrings in managym/__init__.pyi and docs/engine.md now document how their union forms the admitted vocabulary.
  • record_vocabulary::PROGRAM_VOCABULARY & missing_program_tokens(&[(u16, i32)]) -> BTreeSet<(u16, i32)>: single native source of truth shared by the into_rules_tokens debug guard, runtime_only_programs_have_catalog_tokens, observability.rs witnesses, and token_renames.rs.
  • ContentPack::catalog_name(&str) -> Option<&str> & StringField::ChosenCardName: gates chosen card names uniformly across Decision::SearchNamed, ZoneEntry.chosen, Effect::ExileNamed, and FactKind::ChosenName.
  • fixtures-gated unchecked serializer: rules_tokens_unchecked / TokenWriter::into_rules_tokens_unchecked exists only under the fixtures feature so every_effect_variant_reaches_the_learning_tokens can report every missing pair in one pass without disabling the guard on the other 46 observability.rs witness tests.

4. Trade-offs and invariants going forward

  • No 0.2.6 GrantClock shim and no new catalog_tokens() key: followed your steer (ee8ad494). Existing checkpoints stay unaffected (new registrations in execution_names append by name and bind cleanly; both pinned pilots stay bit-identical).
  • Debug-only guard: runs under #[cfg(debug_assertions)] with zero release overhead and no effect on engine perf baselines or state digests. Release self-play still fails closed in Python admission.py.
  • decision_memory=False baseline in the guard: the guard intentionally excludes DecisionMemory::* tokens (refining the steer's literal catalog_tokens ∪ record_names) so no runtime emitter can rely on rows that default policies strip.
  • Storage-ID projection invariant: runtime writers must never serialize storage IDs or derived solver caches (GrantClock, PermanentId, ObjectId, SpendingObject, AbilityGrant). Fix future guard failures by projecting or stripping at the writer rather than registering raw storage structs.
  • Intentional behavior change: decision_memory::snapshot no longer serializes SpendingContext::Activate / SpendingObject (or granted_by) on battlefield permanents with activated abilities. That restores definition_only() deduplication and shifts recorded decision-memory snapshot digests in authored-match parity receipts (see Finding 2).
  • Security note: this diff touches no auth, credentials, network, or untrusted-input boundaries.

5. Findings left outside this PR

record_vocabulary() carries ~360 synthetic ("token", "execution/<kind>/<name>", …) rows solely to shuttle runtime program tokens into catalog.py's record_token_keys, plus 44 DecisionMemory::* rows with phantom Variant tokens (now filtered by !name.starts_with("DecisionMemory::") in four places). Splitting runtime program tokens out directly — and deciding whether catalog_tokens() should be renamed alongside it — breaks checkpoint/API compatibility, so it belongs together as one 0.3.0 Task.

Stripping SpendingObject / SpendingContext::Activate from decision_memory::snapshot in 68c414a1b6 intentionally changed the recorded decision-memory snapshot digest, so test_checked_authored_match_parity_receipt in CI/Academy Integration (contracts) now reports a stale checked receipt (all other 25 CI checks are green). Regenerate and commit the receipt before landing (or let deliver's land --wait-and-fix refresh it).

"creature type choice", "chosen creature type", and "normal combat damage" remain in EXECUTION_TEXT with no live emitter. Removing them on 0.2.x would require six retirement entries in token_renames.rs for no runtime benefit.
