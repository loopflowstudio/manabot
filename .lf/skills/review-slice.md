# Etude play-record review

After changing GameSession persistence, run presentation and Study runtime
integration checks as well as attempt-store checks. Their source-immutability
assertions must read the SQLite trace authority; do not restore a JSON dual write
to satisfy an old fixture. Private REST Study calls require an exact participant
credential even for single-player tables.

Legacy JSON support is read-only. The frozen baseline probe under `scratch/`
targets its recorded base revision; it is not a caller that justifies restoring
the removed JSON writer on the current branch.

Inject recorder failure through the WebSocket surface: a second failure while
closing must not prevent the client from receiving an explicit recording error.

When checking generated deal seeds, replay the retained seed with the same
control opponent and hero decisions. Resolve the seed before constructing both
the environment and policy; matching initial hands alone misses policy drift.

Shared history needs separate listing, replay and feedback permission checks.
Exercise two browser identities, both seats and incomplete attempts; apply
visibility before pagination. Human seat metadata does not prove human play:
automated runs must declare `ETUDE_PLAY_RECORD_ORIGIN=automated_validation`.
Retain the accepted privacy and future data-consumer boundaries in
`docs/evidence/trained-challenger-2026-09-25.md` when evaluating later changes.
